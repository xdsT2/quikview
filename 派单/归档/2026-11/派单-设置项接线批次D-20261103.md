## 四、D1 快捷键自定义

### 现状（已核实）

- 键盘页整表 `markUnavailable(table)`（`SettingsDialog.cpp:1090`），14 行 × 3 列全部不可交互；
- 表里只有 **14 个动作**（open / openfolder / next / prev / next_frame / prev_frame / zoom_in / zoom_out / actual_size / fit / slideshow / crop / favorite / del）；
- 但 `MainWindow.cpp` 实际有 **41 个 `mk(tr(...))` 创建的 QAction**（`:986` 起），键位全部写死；
- `mk` 是构造期 lambda（`:961`），创建时直接绑定 `QKeySequence`。

### 交付

1. **动作注册表**：`MainWindow` 建一个 `QHash<QString, QAction*> m_actions`，`mk()` 增加 `id` 参数并登记；键位不再写死，改为 `Config::actionKey(id, defaultSeq)`。
2. **配置结构**：`keyboard/<action>_enabled`、`keyboard/<action>_key`、`keyboard/<action>_action`（这三类键审计脚本已在统计，共 42 个）。
3. **设置页**：整表解灰，三列接线——
   - 勾选 → `_enabled`，取消则 `setShortcut({})`；
   - 热键 → 用 `QKeySequenceEdit` 替代现有 `QLineEdit`，保存后立即 `QAction::setShortcut`；
   - 操作 → combo 切换绑定到哪个动作（同键不同动作时要互斥）。
4. **冲突检测**：保存时若同一键位被两个启用的动作占用 → 阻止保存并高亮冲突行，提示「Ctrl+P 已被『打印』占用」。
5. **恢复默认**：`onReset` 里把 14 项键位写回 `defaultSeq`。
6. **范围控制**：**本期只做表里这 14 项**。41 个 QAction 全量可配属二期，不要顺手扩表——扩了就要重做 UI 布局和翻译。

### 验收

| 判据 | 做法 |
|---|---|
| 生效 | 把「打开」改成 `Ctrl+P` → 按 Ctrl+P 弹出打开对话框；原 Ctrl+O 失效 |
| 持久 | 重启后仍是 Ctrl+P |
| 互斥 | 把「删除」也设成 Ctrl+P → 保存被拒并提示占用者 |
| 禁用 | 取消「裁剪」勾选 → 按 X 不裁剪 |
| 重置 | `恢复默认` → 14 项回到出厂键位 |
| 不回归 | `--smoke "next10,report"` 仍通过；`→` / `←` / `Space` / `1` / `0` 五个高频键逐个手测 |

### 风险

- `QKeySequenceEdit` 与现有自绘样式可能不一致，需要补 QSS；不接受"能用就行"的原生控件外观。
- 箭头键 `→`/`←` 在某些输入法下会被吞，验收必须在中文输入法激活状态下也测一遍。

## 五、D2 资源管理器壳扩展

### 现状

上下文菜单页 9 项全灰，`ctxmenu/*` 9 个键零消费。安装器目前只写 ProgID / OpenWithProgids / Capabilities（第 13 期），**没有任何壳扩展注册**。

### 键与功能对照

| 键 | 对应能力 |
|---|---|
| `ctxmenu/use_shell_menu` | 总开关：不勾则安装器不注册 handler |
| `ctxmenu/browse_image` | 右键菜单「用 QuikView 浏览」 |
| `ctxmenu/transform_dlg` | 右键菜单「用 QuikView 转换」 |
| `ctxmenu/show_image_info` | 菜单项后附「1920×1080 · 2.4 MB」 |
| `ctxmenu/show_icon` | 菜单项带 QuikView 图标 |
| `ctxmenu/preview_image` | 预览窗格（`IPreviewHandler`，最难，允许后置） |
| `ctxmenu/thumb_webp` | 缩略图提供者支持 WebP |
| `ctxmenu/thumb_psd` / `thumb_psb` | 缩略图提供者支持 PSD / PSB |

### 分三阶段，每阶段独立可验收、可中止

**阶段 1：IContextMenu（最小可用）**
- 新建 `shell-ext/`，**独立 CMake 工程**，不并入主工程；
- 裸 COM 实现 `IShellExtInit` + `IContextMenu`，**不引入 ATL/WTL**（保持 MIT 干净、零新依赖）；
- 菜单两项：「用 QuikView 浏览」「用 QuikView 转换」，调用 `quikview.exe <path>` / `quikview.exe --batch <path>`；
- 注册：`HKLM\Software\Classes\*\shellex\ContextMenuHandlers\QuikView`，CLSID 指向 DLL；
- 输出 64 位 + 32 位两份 DLL。
- **Go/No-Go**：右键任一图片能出两项、点击能打开 → 进入阶段 2；出不来先查注册与位数，不要直接写缩略图。

**阶段 2：IThumbnailProvider**
- 实现 `IThumbnailProvider`，先只做 WebP（Qt 已能解），再考虑 PSD/PSB（需要解析复合文档，工作量大，允许延后）；
- 注册 `.webp\ShellEx\{8895b1c6-b41f-4c1c-a562-0d564250836f}`。

**阶段 3：IPreviewHandler（可选）**
- 预览窗格，只在阶段 1、2 稳定后评估；不承诺交付。

### 硬约束

1. **DLL 崩溃会连带资源管理器崩**——所有 COM 入口必须 `try/catch(...)` 包裹，异常一律返回 `E_FAIL` 快速失败，不许让异常穿出。
2. **注册需要管理员**，安装器已 `RequestExecutionLevel admin`，卸载必须对称反注册（含 32/64 两个视图）。
3. **不做数字签名**的前提下，SmartScreen 可能提示；不要在代码里绕，写进文档说明是预期。
4. **杀软拦截**：壳扩展 DLL 常被误报，验收要在装有安全软件的环境试一次，把结果如实写进交接文档。
5. 总开关 `ctxmenu/use_shell_menu` 关闭时，安装器**不写** handler 注册项——不是写了再靠代码判断。

### 验收

| 判据 | 做法 |
|---|---|
| 菜单 | 右键 jpg/png/webp → 出现两项，点击能打开对应文件 |
| 多选 | 选中 3 张图右键 → 菜单项存在，点击后能处理（或明确只处理第一张，写进文档） |
| 卸载 | 卸载后 `CLSID\{...}` 与 `ContextMenuHandlers\QuikView` 全部消失，重启资源管理器无残留菜单 |
| 缩略图 | 阶段 2 后 `.webp` 在资源管理器显示缩略图 |
| 稳定性 | 反复右键 50 次、打开 20 个文件夹，资源管理器不崩 |
