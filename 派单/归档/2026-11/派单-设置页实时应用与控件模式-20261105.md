# 方案/交接：设置页分组采用即时应用、按钮操作与下拉选项

> 日期：2026-11-05  
> 背景：用户提出“现在设置里面改动都不是实时的”，并参考截图中的分组卡片、开关、下拉和动作按钮，希望设置交互更直接。目标是在 QuikView 现有设置页上建立清楚、一致的交互规则，同时杜绝“界面能改、实际不生效”。  
> 当前实现线索：`SettingsDialog` 目前有统一“保存设置”按钮；普通绑定控件主要在 `onAccepted()` 写配置，窗口关闭/取消走 `reject()` 回滚；外观页有独立的 `saveAppearance()`。本方案是后续实现依据，尚未修改这些行为。

## 1. 设计原则

1. **按操作语义选控件**，不把所有东西都做成勾选框：二态用开关/复选框，互斥档位用下拉或单选组，立即执行动作使用按钮，连续数值用滑块/数值框。
2. **“即时”必须真的即时**：用户改动后立刻观察到承诺效果；不能只立刻写配置，等重启才生效却不说明。
3. **即时应用与取消语义一致**：采用即时应用的设置页，关闭/取消应恢复本次打开前的值（预览式事务）；明确标为“应用后生效/需重启”的设置可以暂存到应用按钮，或明确显示待应用状态。
4. **无效项不能做成可操作控件**：若功能未接通，禁用并说明原因/适用版本，或移除；不能以控件状态或配置已保存冒充完成。
5. **每个设置项有生效时机标签**：即时、保存后、重启后、外部条件满足后（如 Shell 扩展注册）。用户无需猜。

## 2. 控件选择规范

| 功能形态 | 推荐控件 | 示例 | 交互要求 |
|---|---|---|---|
| 二态、可即时撤销 | 开关 | 跟随系统、自动隐藏工具栏 | 切换后主窗口立即变化；窗口取消时恢复打开前状态 |
| 互斥的少数选项 | 分段按钮/单选组 | 画布背景：纯色/棋盘格；主题：跟随/深/浅 | 当前值明显；切换即预览，说明可用条件 |
| 互斥选项较多或名称较长 | 下拉框 | 插值方式、到达首尾动作、GIF 背景模式 | 选中后按标注时机生效；若仅待应用，显示待应用状态 |
| 一次性命令 | 按钮 | 检查更新、恢复提示、重置配置 | 点击即执行并反馈结果；危险操作需二次确认 |
| 连续数值 | 滑块 + 数值输入 | 缓存容量、幻灯片间隔 | 滑动可预览/节流更新；输入框给精确值；边界明确 |
| 文件/颜色选择 | 按钮打开系统对话框 + 预览 | 选择背景图/颜色 | 选择后即时预览；取消对话框不改值；关闭设置可回滚 |
| 外部系统集成 | 状态行 + 按钮 | 文件关联、Explorer 扩展 | 显示已注册/未注册/权限不足；按钮执行后复查状态，不用普通勾选冒充系统状态 |

不要求全页改成截图中的卡片样式。本轮先定义行为和控件语义，视觉重构另行评估；截图仅作交互参考，不视为要求照搬 GuoheView。

## 3. 生效时机分类与实现方式

给当前全部设置项加内部清单（可先用表格，不一定新增 UI 标签）：

- **LIVE**：切换时调用对应运行时 setter/刷新函数，必要时重建视图；配置写入与界面状态保持一致。
- **ON_APPLY**：用户可连续编辑的一组相关项，显示“有未应用更改”；按“应用”后一起生效，取消回滚。
- **ON_RESTART**：确实只能在启动阶段读取的选项。控件旁明确标“重启后生效”；保存后提示需重启，不能写成实时。
- **EXTERNAL**：依赖安装、注册、系统权限或操作系统能力；用实时状态行和显式动作按钮呈现，并在动作后重新探测。
- **ACTION**：点击即执行，不作为持久化偏好存储。

普通 UI 偏好优先做 LIVE。只有证明无法安全热更新（例如语言资源需重启、外部 Shell 注册）才使用 ON_RESTART/EXTERNAL。

## 4. 推荐分阶段改造

### 阶段 0：行为盘点（先做）

为每个控件登记：页面、文案、控件类型、配置键、保存函数、运行时消费点、作用对象、当前生效时机、开/关行为验证方法。把上一份《设置项真实生效审计与整改》结果接入这张表。未核实的标“待测”，不批量改成即时。

### 阶段 1：即时应用基础设施

1. 建立设置会话快照：打开窗口时记住原配置和相关运行态。
2. 将已验证的 LIVE 项接到明确的 apply handler；不要让所有控件只靠 `onAccepted()` 统一写盘。
3. 每项应用后更新运行中的 MainWindow/Canvas/Cache/Theme 等对应对象，再持久化；失败时恢复控件与运行态，并展示错误。
4. Cancel/Esc/右上角关闭恢复会话开始值，包括即时变化；正常关闭确认无需保存按钮。
5. “恢复默认”必须定义为即时预览还是待应用；建议即时预览，取消可回滚。
6. 对 ON_APPLY 页，保存按钮只在有更改时启用；取消丢弃草稿并恢复已即时预览的变化。

### 阶段 2：先改小批已验证项

优先选择副作用小、热更新路径明确的主题、画布显示选项、提示显隐、通知位置等；逐项开/关验证后再启用即时。缓存大小/缓存开关需要检查运行时缓存对象及正在飞行的任务如何更新，不得仅写 QSettings。

### 阶段 3：控件语义梳理

把“执行动作”从勾选框改按钮；把档位选择整理为下拉/单选；把颜色/文件路径改成选择按钮加当前预览；把需重启及外部依赖状态写清。每批按具体页面派单，避免一次重写所有页面。

## 5. 用户流程与回滚要求

- 打开设置 → 切换 LIVE 开关 → 主窗口立即变化 → 再次切回立即恢复。
- 打开设置 → 切换 LIVE 开关 → 关闭设置/Esc → 回到进入设置前状态；配置持久化值也恢复。
- 修改 ON_APPLY 项 → 页面显示未应用 → 按取消不落盘；按应用才生效并保存。
- 操作外部系统按钮 → 显示成功/失败和当前状态；失败不能静默关闭对话框或留下假勾选。
- 多项连续修改时，不允许旧的异步回调在用户切回设置后覆盖新值；重复点应用应幂等。

## 6. 验收门槛

每一项改成 LIVE 前必须有：

1. 实际行为的 ON/OFF 双向截图、日志或可量化结果。
2. 同一会话即时切换的证据。
3. 保存、重启后持久化验证。
4. Cancel/Esc/标题栏关闭的回滚验证。
5. 单项失败时 UI 与实际运行状态不会分叉。

每个控件均标有真实生效时机；全量设置页盘点无“可操作但无行为”的项。被判定未实现的项须禁用并解释、移除或明确排入开发，不能只是调换视觉控件样式。

## 7. 当前已知需重点核对

- 当前统一“保存设置”路径：普通绑定写配置集中在 `onAccepted()`；需要检查它之后是否对运行中组件逐项刷新，不能假设配置写入即生效。
- 外观页 `saveAppearance()` 目前集中在接受设置时落盘。若用户期待主题/材质实时预览，应改为预览+会话回滚，或明确标成应用后生效。
- 语言、文件关联、Shell 扩展等可能需要重启/系统注册，不适合伪装成普通即时开关，应单独建模。
- 近期的设置项真实生效审计仍需逐页实测；本设计不宣称当前具体哪项已失效。

## 8. 建议的首批任务拆分

1. **SET-01 盘点**：生成全量控件与生效时机台账，标记待测/疑似无效；不改行为。
2. **SET-02 会话回滚框架**：实现设置页 LIVE 预览与 Cancel/Esc/关闭回滚，先接主题一个低风险样板项。
3. **SET-03 LIVE 小批 A**：仅接通过审计的低风险二态项，逐项双向验证。
4. **SET-04 控件语义调整**：一次性动作按钮、档位下拉、外部系统状态行；按页面分批。
5. **SET-05 剩余设置项闭环**：继续接线、灰显、删项或排期，直至可操作项全有运行证据。

每项单独明确负责人和验收人。阶段 0 完成后根据真实失效率重排 P0/P1；不预设需要重做整套 UI。
