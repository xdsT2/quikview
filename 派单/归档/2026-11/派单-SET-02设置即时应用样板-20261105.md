## 1. 用户体验定义

本单的“即时应用”指：改变控件后，主窗口立即显示对应效果，不需要另点保存按钮。为了兼顾用户熟悉的取消操作，本单采用**预览式设置会话**：

- 打开设置时记录当前持久化设置和运行状态。
- 切换样板项后立即更新主窗口，并同步保存本次草稿值；窗口底部明确显示“更改已即时预览，关闭设置后保留；取消将恢复”。
- 点击“取消”、按 Esc 或标题栏关闭：恢复打开设置前的全部样板项状态与配置值。
- 点击“完成/关闭”或“应用并关闭”：保留当前值并结束设置会话；不要求用户再逐页点保存。
- **不做设置项每次切换都永久落盘。** 若采用“每次切换立即永久保存”，取消就无法自然回滚，需另立产品决策，本单不采用。

## 2. 本批范围

先做会话基础和一项样板，验证模式后再扩展；不一次把 61 个选项全部改成即时。

### 基础框架

1. 打开设置时为样板项保存原值；明确配置快照范围，不能误清其他设置或运行状态。
2. 预览时调用真实运行时更新函数，不能只改控件和 QSettings。
3. 关闭确认路径保留新值；取消/Esc/右上角关闭路径恢复旧配置并将旧值重新应用到运行实例。
4. “恢复默认”在本单样板项上也按即时预览处理；取消仍恢复进入前状态。
5. 反复切换和重复关闭必须幂等；不得产生多余窗口重建、事件递归或配置覆盖。

### 样板项：深色 / 浅色主题

SET-01 审计推荐此项作为首个样板。当前主题 UI 在 `SettingsDialog` 内；实际主题刷新经 `Theme::applySetting`，主窗口设置接受时也会走主题更新。执行者先核实当前 HEAD 下的真实调用路径，再接入预览。

- 切换深/浅模式后主窗口和设置对话框应在当前会话立即刷新。
- 若“跟随系统”开启，深色模式控件继续禁用；系统模式下不得错误覆盖主题。
- 磨砂材质的系统限制和浅色合规不纳入本项实现范围，只做回归确认。
- 点击取消/Esc/标题栏关闭后，主窗口及设置页恢复进入设置前主题；之后重新打开设置仍显示原主题。
- 点击关闭/完成后，主题持久化；重启后主题保持。

若主题在当前版本架构下无法正确即时预览并可靠回滚，先提交可复现的原因与替代样板建议，不得把“控件状态更新”当作完成。

## 3. 界面文案与按钮

- 移除误导性的“更改会在保存后生效”文案。
- 设置对话框主按钮建议改为“完成”或“关闭”；无需先把所有页面改造成保存事务。
- “取消”保留，语义是放弃本次设置会话的预览改动。
- 文案需明确：切换即预览，关闭后保留；取消会回到进入前状态。
- 若需要多阶段设置（如语言重启生效、外部文件关联），继续使用明确的操作按钮/状态说明，不得伪称即时。

## 4. 必须验证的场景

| 场景 | 操作 | 预期 |
|---|---|---|
| 即时预览 | 深色切浅色 | 对话框与主窗口在当前会话立刻改变 |
| 反向预览 | 浅色切深色 | 立即切回，无残留旧色 |
| 取消回滚 | 切换主题后点取消 | 主窗口和配置恢复原值 |
| 键盘取消 | 切换主题后按 Esc | 等同取消，旧值恢复 |
| 标题栏关闭 | 切换主题后点 X | 等同取消，旧值恢复 |
| 保留设置 | 切换后点完成/关闭，再重开设置 | 新值仍在，主窗口一致 |
| 持久化 | 完成后重启程序 | 新主题保持 |
| 跟随系统 | 开启跟随系统再切 Windows 主题 | 遵循系统；取消设置会话后恢复会话起始配置 |
