## 一、问题与实测依据

用户反馈：打开图片后无法在窗口内拖动，只有放大之后才能拖一点。

实测（同一张 4000×3000 图，同一个 1600×1025 窗口，用真实鼠标事件驱动并做像素差分）：

| 场景 | 果核看图 | QuikView |
|---|---|---|
| 打开后直接拖 220×160 px | 图片跟随移动 | **像素差异 0.00%，完全不动** |
| 放大 4 档后再拖 | 跟随移动 | 移动（差异 6.17%），但滚到内容边界就停 |
| 能否拖出边界留空白 | 能 | 不能 |

**根因**：画布用 `QGraphicsView::ScrollHandDrag`，它的"拖动"本质是改滚动条值。滚动行程 = 内容尺寸 − 视口尺寸。
- fit 态两者相等 → 行程 0 → 拖不动；
- 放大后行程 > 0 → 能拖，但受内容边界限制，永远拖不出白边。

## 三、改动清单

### 3.1 统一场景矩形并加可拖边界（核心）

`ImageCanvas.cpp` 现有两处 `scene()->setSceneRect(m_item->boundingRect());`（`:384`、`:405`），收口成一个私有函数：

```cpp
void ImageCanvas::updateSceneRect()
{
    if (!m_item) { scene()->setSceneRect(QRectF()); return; }
    const QRectF img = m_item->boundingRect();
    // 2 倍视口：能拖出大半个屏幕，正常操作碰不到墙
    const qreal px = viewport()->width()  * 2.0;
    const qreal py = viewport()->height() * 2.0;
    scene()->setSceneRect(img.adjusted(-px, -py, px, py));
}
```

调用点：`setPixmap`、`setPixmapPreservingView`、以及 `resizeEvent`（视口变了，padding 要跟着重算）。

**要求**：`m_item` 的 scene 坐标保持 `(0,0)` 起、尺寸 = 图片逻辑尺寸，**不许**用 `setPos` 挪 item——pad 只体现在 sceneRect 上。

### 3.2 所有归一化坐标改以"图片矩形"为基准（必做）

sceneRect 变大后，任何以 sceneRect 为分母的归一化都会错。已知受影响点：

| 位置 | 现状 | 改法 |
|---|---|---|
| `ImageCanvas::viewCenterNormalized()`（`:428`） | 按 sceneRect 归一化 | 改为按 `m_item->sceneBoundingRect()` 归一化，结果再 `qBound(0,1)` |
| `setPixmapPreservingView(...)` 的 `anchorNorm` 还原（`:422`） | `centerOn(r.left()+anchor.x()*r.width(), ...)` | `r` 必须是图片矩形，不是 sceneRect |
| `MainWindow.cpp:2158 / 2299 / 2694` 三处调用 | 消费上述归一化 | 不改调用方，只保证 3.2 改完语义不变 |

**自检**：调 `viewCenterNormalized()` 在"整图 fit"时应返回接近 `(0.5, 0.5)`；在"滚到图片左下角"时应接近 `(0, 1)`。

### 3.3 顶部对齐改按图片矩形（不做这步，B3 立刻坏）

`applyAlignTopIfLarge()` 现在是 `verticalScrollBar()->setValue(0)`。加了 padding 后 **0 是 padding 的顶，不是图片的顶**。

改为：把图片顶边对齐到视口顶边。

```cpp
const QRectF img = m_item->sceneBoundingRect();
centerOn(img.center().x(), img.top() + viewport()->height() / (2.0 * transform().m11()));
```

### 3.4 光标（可拖时张开手、按住握拳）

`setCropMode(false)` 现在会 `setCursor(Qt::ArrowCursor)`，把 `ScrollHandDrag` 自带的抓手光标盖掉。改为：非裁剪态 `unsetCursor()`，交给 Qt 管理；裁剪态才 `CrossCursor`。

### 3.5 可选：长图轴锁（建议做，成本低）

借鉴 core-ui 的 `panLockX_`：当图片**宽度**在 fit 后不超过视口宽度时（即横向本来就没有溢出），锁住横向平移，只允许上下拖。避免用户把一张长图左右拖偏、再也对不齐。

实现：在 `mousePressEvent` 记 `m_panLockX = (imgWidth * zoom <= viewportWidth)`，`ScrollHandDrag` 本身不区分轴，所以锁轴要用 `setDragMode(NoDrag)` + 手动推滚动条，或者简单些——**这一项标为可选，做不了就跳过，不要为它增加风险**。

# 完成交接（177da83 + 同日返工）

## 实现概述

- `ImageCanvas::updateSceneRect()`：sceneRect = 图片矩形四周加 padding，滚动行程恒 > 0，fit 态可拖、可拖出边界留空白；`m_item` 固定 (0,0) 起，pad 只体现在 sceneRect 上，锚点/归一化逻辑不受影响。
- 左键拖动走 QGraphicsView 原生 ScrollHandDrag；边缘单击翻页（edgeTurnDelta）与拖拽平移的判定互不干扰。

## 当时的缺陷（返工单已确认）

padding 写成场景单位（`viewport()*2`），随 zoom 同比例缩放——zoom 越小行程越缩，约 0.1× 时行程归零完全拖不动。
