## 2. 启动修复与启动自检（回应「找不到 libgcc_s_seh-1.dll」）

此前双击/未注入 PATH 启动，进程在加载 DLL 阶段即退出，弹「quikview.exe - 系统错误 / 由于找不到 libgcc_s_seh-1.dll」。基于该失败进程的截图与结论**全部作废**（清单见 §6）。

修复与固化：

1. **运行库定位**：`build-layout/CMakeCache.txt` 中
   - `CMAKE_CXX_COMPILER:FILEPATH=E:/Agent/Tencent/WorkBuddy/Workspace/tools/msys64/mingw64/bin/c++.exe`
   - `CMAKE_MAKE_PROGRAM:FILEPATH=E:/Agent/Tencent/WorkBuddy/Workspace/tools/msys64/mingw64/bin/ninja.exe`
   - `Qt6_DIR:PATH=E:/Agent/Tencent/WorkBuddy/Workspace/tools/msys64/mingw64/lib/cmake/Qt6`
   - 结论：MinGW 与 Qt6 共用同一前缀，`bin` 目录即 `E:\Agent\Tencent\WorkBuddy\Workspace\tools\msys64\mingw64\bin`（Qt6 的 DLL 也在此）。
2. **启动方式**：所有场景统一执行 `$env:PATH = "<mingw64>\bin;" + $env:PATH` 后再 `Start-Process`；不双击、不依赖系统 PATH。另以 `QUIKVIEW_CONFIG_PATH` 隔离配置。
3. **启动自检（每条证据的前置条件）**：`Assert-Started` 依次校验
   - 进程未退出；
   - 按 PID 枚举可见顶层窗口，且窗口标题 = `设置`；
   - `MainWindowHandle ≠ 0` 且找到标题匹配的 HWND。
   任一不成立即写 `NOT-STARTED` 并抛错，脚本终止——不截图、不写结论。
4. **前台自检**：`Focus-Window` 用 `AttachThreadInput + BringWindowToTop + SetForegroundWindow` 重试 3 次，并校验 `GetForegroundWindow()==hwnd`；失败即 `NOT-FOCUSED` 终止。
5. **尺寸自检**：每次启动后实测 client 宽度，强制等于 125% 基线 `1175`；偏差则用 `QT_SCALE_FACTOR = 1175 / 实测宽` 重启并复测，仍不合格记 `FAIL bad-ui-scale` 终止。日志逐条记录 `dpi / client / uiScale / foreground`。
