## 一、补真实即时生效（快捷键「启用」）

### 改了什么

## 二、统一关闭时的保存处理

### 改了什么
- **唯一写盘入口**：新增 `writeValues()`（`commitValues()` / 即时项 / 兼容桥键 / 关闭重试都走它），删除 `sSet/bSet/iSet` 与 `onAccepted()` 整表写回，设置页内不再有第二套写盘。`retryable` 区分：即时项失败保留内存并记入 `m_pendingWrites` 待重试；热键/语言草稿失败**立即回滚内存**（见第四节）。
- **只提交实际变更的键**：`onAccepted()` 只提交
  - `keyboard/<action>_key`：与进入设置时基线不同者；
  - `keyboard/<action>_action`：仅历史残留值与目标动作不一致时清理；
  - `language`：与基线不同时；
  即时项已在变更点落盘，不重复写；兼容桥键仅推导值不同才写。
- **关闭路径检查写盘错误**：`reject()` 的「直接关闭（无草稿）」与「不保存」在 `flushPendingWrites()` 后检查 `QSettings::status()`；失败弹「保存失败：配置文件写入失败(n)。改动仍保留在界面上，可稍后重试。」并**留在设置页**，不关窗。
- **重试真实可用**：Qt `QSettings::status()` 会被首个错误粘住（实测权限恢复后 sync 已写入但仍返回 AccessError）。`Config::reopenSettings()` 重建同路径实例；下一次写盘前 `refreshSettingsInstanceIfError()` 快照并重放当前内存键，拿到干净状态后再写入，权限恢复后的重试可真正落盘。

### 用什么证明
- `K_ok_nochange`：无改动点「保存并关闭」→ 关窗、无确认、`file_hash_same=true`、键值差异为空（未整表重写）。
- `D_save`：改「启用」+ 改热键 → 差异恰为 `keyboard/open_enabled`、`keyboard/open_key`，无 `_action`、无其他键。
- `O_lang_save`：只改界面语言 → 差异恰为 `language`。
- `A_nochange` / `J_reset` / `H_conflict` 等：直接关闭/恢复默认/冲突拦截均按预期，未回归。
- `I_fail`：保存时写盘失败（目录 ACL 拒绝 WD/AD）→ `warning=true`、`settings_open=true`、`closed=false`（留窗）。
- `L_direct_close_fail`：即时项写盘失败后直接关闭 → 警告并留窗；恢复权限后再点 ✕ → `retry_warning=false`、`retry_closed=true`、`retry_enabled=false` 已落盘（155 字节）。
- `M_discard_fail`：有热键草稿点「不保存」且写盘失败 → 警告并留窗。
- `C_mixed`：启用即时项在「不保存」后保留（`false`），热键草稿丢弃；`F_continue`：继续编辑保留草稿；`E_discard`：语言草稿丢弃；`G_revert`：改回原值后无待保存、无确认框。

## 四、本轮补充：连续路径「保存失败 → 恢复权限 → 不保存」与强杀

### 结论（先给判定）
- **旧 exe（21:32 版）复现脏写**：`不保存` 确实把被放弃的热键 / 语言草稿写进了磁盘，且进程退出后仍在。
- **修复后未复现**：同一操作序列下，写盘失败当时、恢复权限后点「不保存」、进程退出后再读，三段磁盘值均为改动前的 `Ctrl+O` / `system`；同会话重开设置页热键框显示 `Ctrl+O`。
- **强杀未出现部分草稿**：写盘失败留窗期间强杀、以及恢复权限后未做任何操作直接强杀，磁盘均为原值，目录内无临时残留文件。

### 复现（旧 exe `52AA34A8…`，隔离 ini）
操作：键盘页把「打开」热键改为 `A` → 语言页把界面语言改为 `zh_CN` → 目录 ACL 拒绝 WD/AD → 点「保存并关闭」→ 首次写盘失败留窗 → 恢复权限 → 关闭并选「不保存」。

| 阶段 | `keyboard/open_key` | `language` |
|---|---|---|
| 改动前 | `Ctrl+O` | `system` |
| 草稿只在界面（写盘前） | `Ctrl+O` | `system` |
| 写盘失败当时 | `Ctrl+O` | `system` |
| 恢复权限后点「不保存」 | **`A`** | **`zh_CN`** |
| 进程退出后再读 | **`A`** | **`zh_CN`** |

复现时同会话重开设置页也读到 `A`（同一脚本的 reopen 快照；该旧版已重建覆盖，原始终端输出转录见 `Temp/SET-04/closeflow/repro-old-exe.txt`）。根因：`commitValues()` 在 sync 前就把草稿 `setValue` 进 `QSettings`；sync 失败后值仍留在内存与 `m_pendingWrites`，「不保存」路径再次 sync 时把它们刷盘。

### 改了什么
- `SettingsDialog::writeValues(values, retryable, error)` 成为唯一写盘实现；`commitValues()` 仅以 `retryable=false` 调它写热键 / 语言草稿。
- **草稿失败立即回滚内存**：写入前记录每个键的旧值与是否存在；`sync` 失败且 `retryable=false` 时，用旧值 `setValue`（原本不存在的键 `remove`），草稿不再留在 `QSettings` 中。没有采用「丢弃时再写回旧值」，丢弃路径根本不再持有草稿。
- `flushPendingWrites()` 只重试失败过的**即时项**（`m_pendingWrites`）；没有待重试项时不再无条件 sync，「不保存」路径不会为草稿产生任何写盘。`m_forceSync` 仅用于「恢复默认」这类直接改内存的批量变更。
- `onAccepted()` 调整顺序：先重试遗留即时项，失败则不动草稿；成功后才按基线差异提交热键 / 语言，避免「草稿已落盘、窗口还开着」。
- `QSettings::status()` 粘住的处理移到下一次写盘前 `refreshSettingsInstanceIfError()`（重建实例 + 重放内存键），不再在失败当次把草稿重放并 sync。

- `P_save_fail_then_discard`（修复后）：`stage1_fail_disk = Ctrl+O/system`、`stage2_discard_disk = Ctrl+O/system`、`stage3_exit_disk = Ctrl+O/system`；`closed_after_discard=true`；同会话 F5 重开设置页热键框显示 `Ctrl+O`（`P-reopen-key-crop-crop.png`），直接关闭无确认框（`reopen_confirm=false`）。
