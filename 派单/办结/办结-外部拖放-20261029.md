## 一、根因（比交办单多一条，且这一条才是「时好时坏」里更常见的那一半）

### 根因 1（新发现，决定性）：落点在画布上必丢——拖放事件被 `QGraphicsView` 的 viewport 吞掉

`MainWindow::setAcceptDrops(true)` 只管主窗口自己。实际落在光标下的是 `ImageCanvas`（`QGraphicsView`）的 **viewport**——一个普通 `QWidget`，而 `QGraphicsView` 会给 viewport 开 `acceptDrops`。Qt 把 `DragEnter/DragMove/Drop` 交给 viewport 后**不再向父窗口上抛**，`MainWindow::dragEnterEvent / dropEvent` 一次都收不到。

实测证据（诊断期在 `qApp` 上装临时事件过滤器，只记录不拦截）：

```
[evt enter] recv=QWidget acceptDrops=1 chain=QWidget <- ImageCanvas <- MainWindow
[evt move ] recv=QWidget acceptDrops=1 chain=QWidget <- ImageCanvas <- MainWindow
[evt leave] recv=QWidget acceptDrops=1 chain=QWidget <- ImageCanvas <- MainWindow
```

`MainWindow::dragEnterEvent` 没有任何日志输出——不是日志失效（同一次运行里构造函数打的 boot 行正常落盘），是确实没被调用。窗口中间 90% 面积都是画布，所以「多数时候拿不到」。拖到标题栏/工具栏边缘时偶尔能进，看起来就像「时好时坏」。

### 根因 2（交办单已指出）：enter 只认 `hasUrls()` + drop 只取 `urls().first()`

- 延迟渲染源（微信/QQ 常见：拖动中不给 CF_HDROP，松手才渲染）在 enter 阶段拿不到 uri-list → `hasUrls()==false` → 拒收，用户看到禁止光标，drop 根本不发生。
- `dropEvent` 只取 `urls().first().toLocalFile()`：多选时首项可能是 http 链接（`toLocalFile()` 返回空 → 静默失败）；纯 CF_DIB 位图（截图工具/网页）完全没有 URL，原实现完全不收。

## 二、交付

1. **`MainWindow::eventFilter`（新）**：构造函数里 `qApp->installEventFilter(this)`；凡是发往**本窗口子控件**（`child != this && isAncestorOf(child)`）的 `DragEnter/DragMove/Drop`，统一转交主窗口的 `dragEnterEvent/dragMoveEvent/dropEvent` 并返回 `true`。整窗（画布、标题栏、工具栏、状态栏、缩略图面板）都能落图，且不依赖 Qt 的上抛行为。
2. **`dragEnterEvent` 放宽**（同上单要求）：`hasUrls() || hasImage() || formats().contains("text/uri-list"/"text/plain")`，其余只要有格式也收（`!formats().isEmpty()`）。enter/move 阶段**只枚举 formats，绝不读数据内容**。
3. **新增 `dragMoveEvent`**：同样接受 copy，防止部分源中途把光标改成禁止。
4. **`dropEvent` 按序兜底**：
   1. `urls()` 里第一个 `isLocalFile() && QFileInfo::exists()` 的路径（不是拿 first 就用）；
   2. 没有本地 URL 但 `hasImage()` → `imageData()` 转 QImage（`QImage` 取不到再试 `QPixmap`）→ 存 `%TEMP%\QuikView\drop-yyyyMMdd-HHmmss-zzz.png` → `openFile` 该临时文件；
   3. 仍无 → `text()` 按行拆，找 `file://` 开头的行再转本地路径；
   4. 全落空 → 静默 `return`，不弹错、不崩溃。
   成功时统一 `setDropAction(Qt::CopyAction) + accept()`（此前是 `acceptProposedAction()`，某些源 proposed 是 Move）。
5. **未改**：`openFile` 本体、目录索引 `DirectoryLoader`、FIFO 调度、滑块预览通道一律没碰。

## 五、测试环境说明（不影响产品代码，但影响复现）

- 本机桌面常驻「Hydra 下载管理器」（pid 28016，另有 Chrome/WorkBuddy/Trae 全屏窗）会把 QuikView 盖住；`SetWindowPos(..., SWP_NOZORDER)` 时落点会打到别人身上，`DoDragDrop` 照样返回 `DROPFOLDER_S_DROP effect=1`，看起来「成功」但实际没进 QuikView。
  解决办法：测试脚本里对 QuikView 用 `HWND_TOPMOST` 置顶，**并在拖拽全过程每 50ms 重新置顶一次**（只测环境行为，产品代码无关），落点再用 `WindowFromPoint` 校验 pid；拖源侧新增 `HOVER` 日志复核落点。
- 合成拖源必须自己实现 `IDropSource`：`DoDragDrop(obj, nullptr, ...)` 直接返回 `E_INVALIDARG (0x80070057)`（踩过）。
- 跑 `quikview.exe` / `dropsrc.exe` 都要先把 msys64 `mingw64\bin` 加到 `PATH`，否则 `0xC0000135` 秒退；`subprocess.Popen` 必须显式传 `env`。
- 本机 UI 缩放非 100%：底部胶囊 `ControlBar` 逻辑尺寸 440×72，屏幕上约 545×90；页码滑杆的可点区域在窗口内的物理 y≈778（不是视觉上胶囊的顶边）。写自动化别按逻辑坐标硬算。
