# 专项审计：设置项是否真实生效

> 日期：2026-11-05  
> 目的：逐项确认设置界面上可勾选/可编辑、且文案承诺了行为的选项，保存后是否真的改变运行效果。用户反馈“很多确实是文字已经写上去了，也可以勾选，但是实际功能无效”。本专项以运行行为为准，不以 UI 状态、配置落盘或代码里存在 getter/setter 作为完成证据。  
> 范围仓库：`E:\Agent\Tencent\WorkBuddy\Workspace\quikview`。本工单定义审计流程；具体执行仍应按用户派工。

## 1. 验证标准

每个可操作设置项至少完成以下闭环：

1. 记录默认值和当前值；用可复现样本观察基线行为。
2. 只改这一项并保存，确认界面没有假成功提示或被其他设置覆盖。
3. 对即时设置，在当前运行中观察实际行为；对启动时/持久化设置，重启后再观察。
4. 反向切回原值，确认行为反向变化；若两态看不出差异，不能判通过。
5. 记录运行环境、样本、操作步骤、预期/实际、截图或日志、配置前后值、结论。

结论只允许：**行为验证通过**、**行为验证失败**、**部分生效**、**无法验证（写清缺什么）**。仅“配置键变了”“代码有引用”“控件能点”都不能判通过。

## 3. 审计范围与优先级

先做**全量盘点**：逐页列出可交互的 checkbox、combo、spinbox、编辑框、按钮及其旁边的功能文案，并映射到实际读写配置与运行时消费点。再按风险和用户可见程度分批实测，不能只抽查几个就宣称“设置都正常”。

第一批优先检查：

## 5. 失败项整改规则

- 控件能改、配置也保存、但没有真实行为：判假开关，优先修功能接线；若没有实现计划则改成不可交互只读状态并说明原因，或移除。不得保留可点击但无效的状态。
- 只有部分路径有效：文案必须限定实际支持范围，状态行不能写“支持”或“完成”笼统掩盖限制。
- 代码消费点存在但效果相反/时机不对：按 bug 修复，增加能复现用户路径的回归步骤。
- 外部依赖缺失：本机无法验证与功能本身未实现要分开记录。设置页应诚实展示“未安装/未注册/系统不支持”等真实状态。
- 每个整改切片有明确验收并独立可回滚；不要把多个不相关设置项绑成一个难以定位的“大修”。

## 6. 专项完成定义

1. 当前设置页所有可交互项均有清单；页面/文案/配置键/实际消费路径能对应。
2. 每项均有双向行为验证或明确的“无法验证”原因；无“只因键落盘就通过”的条目。
3. 可操作项中，行为失败、部分生效、无法验证项都有负责人和下一步；无静默假开关。
4. 对需灰显或删除的项，附用户可理解的状态说明/决策依据，不擅自删除有兼容价值的历史配置键。
5. 完成一轮回归后再更新 `PROJECT-PLAN.md` 与对应推送/交接账本，逐项同步状态。

## 7. 工作节奏

- 先交盘点清单和首批实测结果，再开始大规模修复，避免一次性改太多、无法定位回归。
- 执行者每批只负责有限几个同类选项；验收人独立按表复测至少一个开/关往返。
- 高风险设置（文件关联、卸载、Shell COM）先用隔离测试账号/虚拟机；当前环境不具备时标记无法验证，不在日常系统上冒险改默认应用或注册扩展。
- 第一轮优先产出真实问题列表及估算，再按用户可见影响排期；本工单本身不授权推送、发布、安装/卸载或删除数据。

# 二、SET-01 五类打标与「无统一保存按钮」落地路径

## SET-01 · 五类打标与「无统一保存按钮」落地路径

> 目标形态（用户 11-05 18:18 明确）：设置页去掉底部统一「保存设置」按钮，
> 改为「即时应用 + 会话快照 + Cancel/Esc/标题栏关闭回滚」，关闭窗口不再需要保存动作。
> **本段只给落地路径，不实施**；阶段 0 禁止改 `onAccepted()` / `saveAppearance()` 的保存路径、
> 禁止启动 SET-02 的 LIVE 框架、禁止删除保存按钮。

### 2.1 现状结论（代码核对 + 运行态探针）

`SettingsDialog::onAccepted()` 是**唯一写盘入口**：所有绑定控件（`m_chkBinds` / `m_comboBinds`）
与专项控件（缓存大小、键盘 14 行、鼠标 7 行、书签、路径、语言、外观三态）都只在
按下「保存设置」/ Enter / `accept()` 时写 QSettings。保存返回后 `MainWindow::onSettings()`
才统一执行 `UiStyle::setBlurMaterial` / `Theme::applySetting` / `applyRuntimeSettings()` /
`applyShortcutConfig()` 重装运行态；其余多数 getter 在**行为发生时**惰性读取。

因此现状五类分布的真实结论是：

| 五类 | 现状项数 | 说明 |
|---|---|---|
| **LIVE** | **0** | 现状没有任何「改控件即生效」的项——连主题都要等保存才重装 |
| **ON_APPLY** | 绝大多数持久化项 | 统一「保存设置」按钮事实上充当 Apply；无按钮即全部悬空 |
| **ON_RESTART** | 3 | `language` / `allow_multiple_instances` / `check_updates`（仅 `main.cpp` 启动读取） |
| **EXTERNAL** | 格式关联 2 按钮、上下文菜单状态行、语言页 2 链接、监视器 ICC（禁用） | 依赖系统设置/安装包注册/浏览器，不是偏好键 |
| **ACTION** | 16 个框架按钮 + 检查更新 + 杂项 6 按钮 | 点击即执行，不持久化 |

**这条结论决定了删按钮的门槛**：现状 100% 的持久化项依赖统一保存按钮，
直接删按钮会让全页变成「改了不生效」。必须先完成 SET-02~SET-05 逐项闭环。

### 2.2 五类在「无保存按钮」形态下的落地路径（逐类，不留空）

#### LIVE — 即时应用

- **值何时写入**：控件信号（`toggled` / `currentIndexChanged` / `valueChanged` / `editingFinished`）
  触发时**立即写配置并立即下发运行态**，不等任何按钮、不等窗口关闭。
- **何时生效**：同一次事件循环内更新运行中的 MainWindow / ImageCanvas / ImageCache /
  Theme / QAction 等对象，用户当场可见；写入失败则恢复控件与运行态并展示错误。
- **给用户可见的待生效提示**：**不需要待生效提示**（没有待生效状态）。但按
  `QUIKVIEW-DESIGN.md` §3.7，控件旁仍需常驻「即时」生效时机标签，让用户无需猜。
- **会话快照与回滚**：打开设置时快照必须同时包含 ① `config` 组全部键值
  ② 运行态对象状态（主题模式、画布 flag、快捷键、窗口置顶等）。
  Cancel / Esc / 标题栏关闭 → **配置与运行态一起回滚**；正常关闭 → 保留已写入值，无保存动作。
- **当前实现差距**：`takeSnapshot()` / `restoreSnapshot()` 目前只快照/恢复 `config` 组，
  不覆盖运行态；这是 SET-02 必须先补的框架。

#### ON_APPLY — 应用后（本形态下不默认保留任何按钮）

方案 §3/§4 的「显示未应用更改 → 按应用一起生效 → 保存按钮只在有更改时启用」
**不能直接照搬**：最终形态没有底部统一「保存设置」按钮，派单也明确
「ON_APPLY 页若确需保留『应用』按钮须单独报批，不得默认保留」。落地顺序：

1. **默认路径 = 消除该类**：SET-03~SET-05 把 ON_APPLY 项**逐项改造成 LIVE**
   （每项需双向行为证据 + 取消回滚证据）。这是唯一无需报批的路径。
2. **确需成组提交的**（如「缓存开关 + 缓存大小」、「图片文件夹 1/2 + 编辑器路径」）：
   改为**页内局部提交**——在该分组区块内放一个「应用这组」小按钮 +
   分组级「N 项待应用」状态行；它与底部统一保存按钮是两回事，**必须单独报批**并写明范围。
3. **报批不通过**：该组必须拆成 LIVE 单项，绝不允许保留「改了但没生效」的悬空态。
4. **改造完成前的暂存语义**：草稿只存内存**不写盘**；控件行右侧显示「待应用」徽标，
   页面顶部显示汇总条「N 项待应用」；关闭窗口时草稿丢弃并回滚所有即时预览。
   提示必须是可见状态行，不能只靠按钮变亮。

#### ON_RESTART — 重启后

- **值何时写入**：控件变更时**立即写配置**（避免关闭时丢值），但**不改动本次进程的运行态**。
- **何时生效**：下次启动由 `main.cpp` 读取并生效。
- **给用户可见的待生效提示**：控件旁常驻「重启后生效」标签；一旦当前值与
  **本次启动时的值**不同，追加「已更改 · 重启后生效」徽标，页面顶部汇总「N 项将在重启后生效」。
  关闭窗口后徽标应继续可见（可由主窗口标题栏/菜单状态承载），不能弹一次「请重启」就算完成
  （`QUIKVIEW-DESIGN.md` §6.3/§6.4）。
- **回滚**：因值已写盘，Cancel / Esc / 标题栏关闭必须把配置值恢复为会话快照，
  并清除徽标——这正是快照必须覆盖配置值的理由。
- **禁止**：写成「即时」或保存后提示成功即宣称完成。
- **逐项理由**：`language`（QTranslator 仅 `main.cpp` 启动 `load`；且历史实测语言切换
  整体失效，须先修功能再谈时机）、`allow_multiple_instances`（QLocalServer 单实例管道
  在启动时建立）、`check_updates`（启动 5s 静默检查一次）。

#### EXTERNAL — 外部条件

- **值何时写入**：**不写偏好键**。这些不是二态偏好，用只读状态行 + 显式动作按钮呈现
  **真实系统状态**（已注册 / 未检测到 / 权限不足 / 系统不支持），动作执行后立即重新探测并刷新。
- **何时生效**：由外部系统决定，动作成功后即时复查状态。
- **给用户可见的待生效提示**：状态行本身就是提示；动作失败不得静默关闭对话框或留下假勾选。
  对于「待重启资源管理器才可见」这类，状态行需明确写「已注册，重启资源管理器后可见」。
- **回滚**：不写盘 → 无副作用可回滚；会话快照与这类无关。
- **本单限制**：不做文件关联、注册 Explorer 扩展、安装/卸载等外部副作用测试 →
  相关项一律标**无法验证**并写明缺什么（需隔离测试账号/虚拟机 + 管理员权限）。
- **逐项**：格式关联 2 按钮（`ms-settings:defaultapps` / `IApplicationAssociationRegistrationUI`）、
  上下文菜单 9 条只读状态行（`quikthumb.dll` 随安装包注册）、语言页 2 个 LinkLabel、
  `imageproc/monitor_icc`（Qt6 光栅后端不支持显示器色彩管理，永久灰显 + Tooltip 说明）。

#### ACTION — 一次性动作

- **值何时写入**：不写（检查更新、导航、关闭、浏览/打开/预设、关于）。
  **例外**：「恢复默认」会清空 `config` 组，最终形态下必须定义为**即时预览 + 可回滚**
  （方案 §4.1(5) 建议），会话快照要能整体恢复。
- **何时生效**：点击即执行并给出结果反馈；危险操作二次确认。
- **待生效提示**：不需要；但结果反馈必须可见（成功/失败/当前状态）。
- **落地**：按钮保留并接好执行与反馈；「保存设置」按钮在 SET-05 全量闭环后才移除。

### 3.6 审查发现：假开关与缺陷点名

1. **本轮未新增确认的「可操作但无行为」假开关**：静态核对 59 个 getter 中 4 个零调用
   （`showSelectLangDialog` / `thumbnailSize` / `smoothZoom` / `recentFiles`）在设置页
   **没有对应控件**，属死代码，不算假开关；`imageproc/monitor_icc` 已 `setEnabled(false)`
   且带 Tooltip 说明，符合「禁用项须可读并解释原因」。上下文菜单页 9 行全为只读状态行。
2. **`language`（语言页下拉）是历史已确认的假开关候选**：10-25 实测「写配置通、加载断、
   38/384 条翻译覆盖率」；本轮未复测（组 C），须在 SET-05 前修复或灰显说明，**不得**只换控件样式或文案。
3. **【新发现】`mouse/click_side_pageturn` 默认值不一致**：设置页 `addCheck(..., def=false)`
   与 `Config::sideClickPageturn()` 默认 `true` 相反。隔离 ini 缺该键时，仅「打开设置 →
   直接保存」就会把 `config/mouse/click_side_pageturn` 写成 false（本次 rollback.ini 实测：
   `cfgSide 1→0`、落盘 `mouse\click_side_pageturn=false`），导致边缘单击翻页被静默关闭。
   真实用户配置一般由 `etc/migrated_side_click` 迁移写有 true 而规避，但仍属隐患。
   建议：统一设置页默认值，或在 SET-04 控件语义整改时一并修；**不在本单改行为**。
4. **`A03` 磨砂材质 ON/OFF 截图 0% 差异**：该开关只影响右键菜单与信息浮层，
   `--screenshot` 抓的是主窗口，未打开菜单/浮层 → 属观测口径不足，需专项截图（组 A）。
5. **现状五类 LIVE = 0**：设置页 footer 常驻「更改会在保存后生效」（page0.png 可见），
   与代码核对一致 —— 删按钮前必须完成 SET-02~SET-05 全量闭环。
