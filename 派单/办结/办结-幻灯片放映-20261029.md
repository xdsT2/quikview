## 一、根因

同一条「设间隔」有两份实现，行为不一致：

| 入口 | 原实现 | 未放映时点它 |
|------|--------|--------------|
| Ctrl+1..9 → `onSlideshowInterval(sec)` | 写配置 + `setInterval` + `if (m_slideshow) start() else actSlideshow->setChecked(true)` | 勾上 `actSlideshow` → `toggled` → `setSlideshow(true)` → **开始放映** ✅ |
| 工具栏「幻灯片放映」下拉菜单选「N 秒」→ 内联 lambda | 只写配置 + `setInterval` + `if (m_slideshow) start()` | **什么都不发生** ❌ |

菜单里也没有「开始放映」项（只有「停止放映」）。工具栏幻灯片按钮是主界面唯一入口，点开是下拉菜单 → 从主界面**永远无法启动放映**，用户看到的就是「幻灯片播放，它实际上并不播放」。

## 二、交付

```cpp
for (int s : seconds) {
    const QString shortcut = s <= 9 ? QStringLiteral("Ctrl+%1").arg(s) : QString();
    // 与 Ctrl+1..9 共用同一份实现：未放映时选秒数 = 立即开始放映；
    // 放映中选秒数 = 只换节奏，不打断。
    QAction *a = addCheckableItem(menu, tr("%1 秒").arg(s), shortcut, currentSec == s,
                                  [this, s]() { onSlideshowInterval(s); });
    intervalGroup->addAction(a);
}
```

- 菜单里那份重复逻辑（写配置 / `setInterval` / `if (m_slideshow) start()`）删除，单写者：`onSlideshowInterval()`。
- 「停止放映」保持现状（`actSlideshow->setChecked(false)` → `setSlideshow(false)`）。
- 施工中警告已核：10-28 23:59 的未提交修改就是第 7 期拖放修复，已单独成单 `5dc38df`，与本期不冲突；本期基于 `5dc38df` 起手。

## 四、自查：放映中手动翻页 / 拖页码滑杆会不会打断？（结论：都不打断，无需改代码）

- **手动 next**：见口径 5，`3.2 / 6.4 / 9.2s` 继续自动跳 → 不打断。
- **拖页码滑杆**：放映中 `Ctrl+3` 开始，按住滑杆从 `01.png` 拖到 `07.png` 松手，随后自动跳 `07 → 08 → 09 → 10`（松手后 2.8 / 5.6 / 8.8s），进程存活 → 不打断。
  代码侧也能对上：滑杆只走 `pageRequested` → `m_dir->setIndex()` + `jumpTo()`（= `cancelPending` + `loadAsync`），`jumpTo` / `loadAsync` 里没有任何 `setSlideshow(false)` / `m_slideshowTimer->stop()`。

> **一次误判记录（写下来免得下次再踩）**：第一次测这一格时看到「拖完滑杆 7 秒无自动跳」，差点当成打断去改代码。加临时诊断日志（`setSlideshow` / `onSlideshowTick` / `pageRequested` 落 `%TEMP%\qv-slide.log`）后真因暴露：
> ```
> pageRequested(6) slideshow=0      ← 只有这一行，tick 一次都没有
> ```
> 即 **`Ctrl+3` 根本没送到窗口**——`SetForegroundWindow(h)` 返回但前台仍是别的窗口（前台锁），键盘事件发给了别人。改成「先点一下画布取得前台，再校验 `GetForegroundWindow()==h`」后，同样操作 `tick` 按时到达、滑杆前后节奏连续。诊断日志已全部删除，最终二进制与 `da14796` 一致（`git status` 干净）。
