## 1. 现状与参考（两张截图 + 源码核对）

**截图①（当前 QuikView 外观页）**：主题区是复选框「跟随系统」「深色模式」，提示「跟随系统关闭后，可用上面的开关手动选择深色或浅色。」；材质区「磨砂材质（右键菜单与信息浮层）」；副标题「主题与材质。跟随系统时由 Windows 的深浅色设置决定。」；底部「更改会在保存后生效」/ 恢复默认 / 取消 / 保存设置。

**截图②（用户指定参考形态）**：卡片式分组 + **拨动开关**；「跟随系统」（关，说明「深色/浅色随 Windows 设置自动切换，开启后不能手动切换深色模式」）、「深色模式」（开，蓝色）、「使用磨砂材质」（关，说明「开启后，图片右键菜单以磨砂玻璃效果显示」）。

**源码**：`m_followSystem`（「跟随系统」）与 `m_darkToggle`（「深色模式」）两个复选框**写同一个 `theme` 键**（`dark|light|system`，默认 `dark`）；跟随系统开启时手选开关被禁用，注释写「否则两者写同一键互相打架」。

- 材质区独立键 `ui/blur_material`，**本单不改功能**。
- 底部保留「保存设置」按钮与「更改会在保存后生效」文案。
- 底层三档能力已存在：`fd70489`（三档解析）、`2842e77`（外观页）、`621aa16`（浅色真实现）、`7af4215`（浅色视觉修正）。**本单改的是控件表达与生效时机，不是重做主题能力。**

## 2. 目标形态（用户定制：按图改，保留跟随系统）

主题区保留**两个拨动开关**：「跟随系统」不变，把「深色模式」换成「**浅色模式**」（沿用截图②的拨动开关质感）。

**拨动开关轨道做成胶囊形**（用户 2026-11-06 确认「很多胶囊型的按钮」即指此，非成组 pill button、非底部胶囊浮层）：两端半圆、滑块圆形；建议轨道 20px 高、圆角 10px——正好复用设计规范 v1.2 §4.2 已登记的 `10px` 圆角档位，**不新增色值、不新增圆角档位、不做卡片式分组**。按 §4.2「新增控件优先复用上表；确需新值，先在 `UiStyle.h` 定义常量、在本表登记」的要求，须在 §4.2 登记「开关轨道 20px 高 / 圆角 10px」这一新控件尺寸，并用 `UiStyle.h` 已有令牌实现深 / 浅两套。若实测 20px 高与 30px 行控件不协调，改用能整除的既有尺寸并同步登记，**不得自行引入 15px 之类的新圆角值**（《设计规范-QUIKVIEW.md》v1.2 第 19 行禁超过 10px 的圆角；`docs/design/QUIKVIEW-DESIGN.md` §3 第 23 行要求沿用已有档位）。

| 跟随系统 | 浅色模式 | 落盘值 | 实际表现 |
|---|---|---|---|
| 开 | **禁用不可操作**（灰显并说明原因） | `theme=system` | 深浅由 Windows 决定，系统主题变化实时跟随 |
| 关 | 开 | `theme=light` | 强制浅色，不受系统深浅影响 |
| 关 | 关 | `theme=dark` | 深色（跟随系统关闭时的默认底色） |

- **「深色模式跟随系统」按此落地**：不再提供名为「深色模式」的手动入口；跟随系统开启时深色由 Windows 决定，手动档只保留「浅色模式」。若监工侧理解有偏差，改单后再实施；执行侧不得自行扩展成三档或合并成单一开关。
- **文案同步重写**（三处，逐条说明改动原因）：截图②「开启后不能手动切换深色模式」→ 相应改为浅色模式；截图①「跟随系统关闭后，可用上面的开关手动选择深色或浅色」→ 改为符合新语义；副标题若语义仍成立可保留。不得留旧文案误导。
- **历史值**：`theme=dark` 读入后应正确映射为「跟随系统关 + 浅色模式关」，不得出现「配置是 dark、界面显示不一致」的状态矛盾；处理方式写进交付说明。
- **材质项**：功能与键值不动；控件形态与主题区统一为拨动开关即可，文案沿用项目现有体系，**不照抄参考图的「使用磨砂材质」等产品文案**。
- **卡片式视觉不在本单范围**：方案 §2 末尾明确「不要求全页改成截图中的卡片样式，视觉重构另行评估」。本单只换控件形态与质感，不做卡片分组重构；若要连卡片一起改，须另立定制项并单独标注。

## 3. 生效时机：即时预览（用户 2026-11-06 明确选择）

> **别重复造轮子**：主窗口菜单「深色模式(&D)」的 `QAction::toggled`（`MainWindow.cpp:1114-1121`）已经是「写 `config/theme` + 调 `Theme::applySetting`」的即时路径，`621aa16` 起底层就支持「切深浅立即生效」，`Theme::installSystemWatcher` 还会跟随 Windows 深浅色实时切换。本单是把**设置页**接到这条现成能力并补会话回滚，**不是重新实现主题切换**。当前矛盾只是同一个 `theme` 键：菜单即时、设置页要保存。

复用 SET-02 已落地的 `applyLiveSetting` / `restoreSnapshot` / `rollbackLiveSession` / `QUIKVIEW_TEST_LIVE_FAIL` 框架：切换即更新运行中主窗口与设置页，取消 / Esc / 标题栏 ✕ 恢复会话开始值（含运行态），「保存设置」后持久化、重启保持。

### 3.1 前置评估（必须先做，不满足就回退）

SET-02 曾判定主题热更新涉及 `UiStyle` 重建与浅色分支、回滚不可靠，并把主题排除在 SET-03 之外。本单用户要求即时预览，故**先做一次可复现的评估**：

1. `Theme::applySetting` 在当前 HEAD 下能否在同一会话内反复深/浅切换而不残留旧样式、不产生多余窗口重建或事件递归。
2. SET-02 的会话快照能否覆盖 UiStyle 重建后的运行态（令牌、QSS、浮层几何），取消后能否逐像素回到进入设置前的状态。
3. 跟随系统开 / 关两态与「浅色模式」禁用态切换、以及跟随系统模式下切换 Windows 深浅色，是否互斥正确、不互相覆盖、不留下假开关。

评估通过才继续实现即时预览；**若任一项无法可靠回滚，不得据此结案，也不得把「保存后生效」当作最终形态**（用户 2026-11-06 11:41 明确：不用保存才是最佳体验，即时化是硬目标）。此时必须书面提交可复现原因与像素级证据，并同时给出：① 运行态回滚的修复方案 ② 另立单计划与排期 ③ 临时过渡态说明。「保存后生效」只能作为**标注清楚的临时过渡态**，回执须写「即时预览未实现 / 未验收」，不得写「通过」；即时化作为遗留硬目标继续排队，不得从目标中移除。任何回退决定须报监工侧确认。

## 4. 硬规则

- 颜色与尺寸令牌只从 `src/UiStyle.h` 取；Qt Widgets/QSS 不得照搬 Web/CSS；覆盖默认 / 悬停 / 按下 / 焦点 / 禁用 / 选中相关状态，焦点可见。拨动开关的「关 / 开 / 禁用」三态尤其要在深、浅主题下都可读。
- **保留「保存设置」按钮**：四条删按钮门槛仍未全绿，禁止删 / 改名按钮；本单所有文案改动须逐条说明原因。
- 禁用项须可读并解释原因，不留可操作假开关；每个设置项写清真实生效时机。
- 测试配置隔离：运行前记录 config.ini 哈希，结束恢复复算；不污染用户配置；不做文件关联 / 注册扩展 / 安装卸载等外部副作用测试。
- 每项单独 commit（`feat(外观页): 描述`），单写者不开并行；截图证据放 `派单/证据/`（不入库），单据正文入库；不新建 `交接-*.md`、不把单据放仓库根、不新增 M 行。
- **本单独立于 SET-03**：SET-03 明确排除主题，不得把本单成果计入 SET-03 的 LIVE 计数，也不得借本单顺手改其它设置项。

## 5. 验收点（按 `docs/design/UI-REVIEW.md` 模板填报，未测项不得写成通过）

1. 两个开关在「跟随系统开 / 关 × 浅色模式开 / 关（含禁用态）」全部有效组合下的双向行为证据 + 改前基线截图；深 / 浅两套主题都实际运行并亲眼看自渲染结果。
2. 同一会话反复切换、跟随系统下切换 Windows 深浅色，无残留、无递归、无互相覆盖；禁用态不可操作且说明可读。
3. 「保存设置」后重启持久化读回；历史 `theme=dark` 配置读入不出现状态矛盾。
4. Cancel / Esc / 标题栏 ✕ 三条链路的**运行态**回滚（不是只看配置值）。
5. 失败注入时 UI、运行态、配置三者不分叉。
6. 高 DPI（1.25）、940×800、浅色与深色下改后三处文案完整无截断、控件六态齐全、焦点可见；**胶囊轨道 20px 高 / 10px 圆角在两套主题下实测**，§4.2 已登记新控件尺寸，未引入 15px 之类新圆角值或裸色值。
7. 附实际操作结果、截图绝对路径、未测项清单；构建成功或配置落盘不算验收。
