## 2. 每项验收点（逐项填表，缺一不可）

1. **ON/OFF 双向行为证据**：两态各一次真实行为触发，至少含反向切回；给触发前后截图（或像素差 / 运行态日志）与 ini 读回值。只记录配置变化不算通过。
2. **切换即预览**：设置对话框仍打开时变更该项，须有用户可见的即时反馈（见 §3）。
3. **关闭即保留、不用保存**：不点「保存设置」，以正常退出路径离开设置页，配置值与运行态都保留；重启后读回一致。
4. **三链路运行态回滚**：分别走 取消 / Esc / 标题栏 ✕，配置值**与运行态**同时回到进入设置前；非仅比对配置值。
5. **失败注入**：`QUIKVIEW_TEST_LIVE_FAIL=1` 下 UI、运行态、配置三者不分叉。
6. **回归**：「保存设置」旧路径不回归、#5 `always_on_top` 既有 LIVE 行为不回归、深 / 浅主题与 100% / 125% DPI 下相关状态截图。
7. **生效时机标注**：每项写清真实生效时机；底部 footer 若仍为「更改会在保存后生效」，须按本批结论同步，不得让「即时项 + 全页统一保存后生效」并存误导用户。
8. 按 `docs/design/UI-REVIEW.md` 模板填报；未测项、未达标项单列并写清原因，**不得写成通过**；仅「配置落盘成功」或「控件状态更新」不构成通过。

## 3. 模态可见性（总纲 §2，硬要求）

设置页为模态 `dlg.exec()`，#3 删除确认、#4 toast、#6 Esc 等效果在设置会话内原本不可自然观察。**不得只把控件换成胶囊 / 只接上 setter 就算完成**：须给出设置页内可见的即时反馈（例如内联状态行 / 预览提示，说明该项已即时生效及可观察的触发方式），或提供非模态预览入口；无法在会话内观察的，须在回执里写明阻断原因与用户可见反馈形态，不得以「配置已写」冒充即时生效。
