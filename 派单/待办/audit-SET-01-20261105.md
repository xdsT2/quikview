## 1. 判定口径

| 时机 | 定义 |
|---|---|
| LIVE | 控件切换时立即调用运行时 setter/刷新，无需关闭对话框 |
| ON_APPLY | 关闭对话框（保存）后由 `MainWindow::onSettings()` 统一刷新生效，无需重启 |
| ON_RESTART | 消费点只在启动路径（`main.cpp` / 构造函数）读取，保存后必须重启 |
| EXTERNAL | 依赖系统注册/权限，应用内只能唤起系统入口或只读展示 |
| ACTION | 点击即执行，不持久化为偏好 |

状态：**已核实（静态）** = 写入路径与运行期消费点代码闭合、未见可疑点，本轮**未做运行时实测**（SET-03 前仍须双向实测）；**待测** = 链路存在但依赖特定条件/视觉判断；**疑似无效 / 部分疑似无效** = 代码证据显示无消费点或与文案不符。

## 4. 与设计规范 §7.3 相关的判定提醒

- 外观三项的判断依据只到「关闭对话框后 `Theme::applySetting`」（`MainWindow.cpp:4068`），**不能以「配置写了」判生效**；浅色须按 §7.3 令牌/对比度矩阵逐项核验（导航未选中 6.92、链接 5.54、副标题 6.05 等）。
- §7.3 规则 1「半透明底一律不得用于浅色浮层」与 AP-03 存在潜在冲突：磨砂只按 Windows 版本灰显（1127-1130），不按主题灰显。浅色 + 磨砂需实测是否产生半透明白浮层；若出现，SET-04 应做主题联动或限定深色。
- §7.3 规则 3「深色常量禁止直接进浅色路径」：本次不涉及取值，但外观页改动在 SET-03 必须附深色零回归证据。

## 5. 附加发现（非设置语义，但影响「是否真的保存」）

1. `onAccepted()` 冲突拒绝被两个出口绕过（`776-779`、`2077-2080`）——影响 14 个键盘项，优先级最高。
2. `onAccepted()` 先写键盘/鼠标/缓存……最后才 `saveAppearance()`（1825）；若中途异常，外观与其余项落盘不一致（概率低，但说明「单一落盘点」并未真正事务化）。
3. `ui/blur_material` 的注释称「在 config 组外」（1122），实际键为 `config/ui/blur_material`（Config.cpp:67），恢复默认会清掉它——注释与事实不符，且 UI 不重载。
