## 2. 每项验收点（逐项填表，缺一不可）

1. **四项 LIVE 三链路逐项结论**：#33/#34/#35/#36 各给「切换即预览 / 关闭即保留 / 取消·Esc·✕ 运行态与配置同步回滚」三链路证据。启用项：会话内切开关后对应 `QAction` 快捷键即时挂上 / 卸下；热键项：会话内录入新键后旧键即时失效、新键即时生效（不点保存、不重启、不关闭设置页）。不得只比对配置值。
2. **双向行为证据（真实按键 / 运行态探针）**：#33/#35 各给 enabled=true / false 两态 → 运行态 `keys=` 中该动作是否挂键 + 真实按 Ctrl+O / F 有无反应；#34/#36 各给改键前 / 改键后两态 → 新键真实触发「打开」「打开文件夹」动作、旧键无反应，记录键位字符串比对与真实事件日志。只记录代码分支存在或控件状态更新不算通过。
3. **会话内可见性**：设置页仍打开时，切换 / 改键的反馈必须页面内可见（表格行状态、冲突高亮、状态行或运行态探针输出），不得只在关闭设置页后、或只在主窗口才能看到结果（总纲 §2、§1.1 第 5 条）。
4. **冲突即时化与出口一致性**（§1.1 第 4 条）：录入与既有动作冲突的键位 → 会话内即时高亮 / 拒绝提示，明确拒绝时**不关闭对话框**、不静默丢弃同页其它项改动；「保存设置」与 Enter 两个出口分别走一遍，行为一致；冲突解除后 LIVE 状态恢复。给改前（缺陷可复现）与改后（已消解）两态证据。
5. **不落盘污染与配置零污染**：用 `QUIKVIEW_CONFIG_PATH` 指向隔离 ini，运行前后记录 `build/config.ini` SHA256，须完全一致；取消 / Esc / ✕ 三条链路读回值一致、不新增键、不残留中间态。
6. **三链路运行态与配置回滚**：分别走 取消 / Esc / 标题栏 ✕，配置值**与设置页运行态**（表格行启用态、热键录入内容、冲突高亮、残留弹窗）同时回到进入设置前；非仅比对配置值。

## 3. 会话内可见性与实现边界（总纲 §2 / §3 / §4）

- 运行时消费点 `MainWindow::applyShortcutConfig()` 目前由 `MainWindow.cpp:4072` 在**对话框关闭后**调用，这是「切开关不改变运行态」的根因。本批须在会话内即时触发快捷键重装（复用 SET-02 的 `applyLiveSetting` / `restoreSnapshot` / `rollbackLiveSession` 框架管理运行态快照与三链路回滚，不另造轮子），并让重装结果在设置页内可观察；不得靠「关掉设置页再生效」冒充即时。
- 模态 `dlg.exec()` 会拦截主窗口交互，故真实按键验证须明确取证方式：设置页内热键录入控件自身可接收按键、主窗口运行态可用探针 / 日志 / 状态行观察；若确需在设置页打开时验证主窗口 `QAction` 响应，须给出所用入口与可复现步骤，不得只写「无法自动化」。
- **不得只把控件换形态、只接上 setter、只写时机标注、或只加一行 hint 就算完成**；不得以「配置已写 / 代码已改 / 已胶囊化」冒充即时生效。
