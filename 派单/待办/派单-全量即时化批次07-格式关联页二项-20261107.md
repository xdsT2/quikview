## 2. 每项验收点（逐项填表，缺一不可）

1. **三要素逐项结论（#31、#32 各一份）**：① 尝试即时化的可复现结论——写清为何应用内无法即时完成默认关联（Windows 10/11 `UserChoice` 带哈希、程序不得静默改默认），给代码级或实测可复现依据；② 用户可见的即时反馈——点击后在设置页内立即呈现「正在请求 / 已请求启动系统设置 / 启动失败（错误码或 HRESULT）」的状态行或按钮态，不得点了无反应，也不得以「系统侧结果需你自行确认」代替应用内状态呈现；③ 明确生效时机标注——写清「应用内不落盘、由 Windows 侧决定、需用户在系统界面确认后生效」，不得写成「保存后生效」。
2. **双向 / 两态行为证据**：#31 `ShellExecuteW` 返回值 >32（成功）与 ≤32（失败）两态、#32 `CoCreateInstance` + `LaunchAdvancedAssociationUI` 成功与 `HRESULT` 失败两态，各一次真实触发，给点击前后设置页截图、按钮文字 / 禁用态、弹窗或状态行、日志中的返回值；只记录代码分支存在不算通过。失败态可用不可达路径或注入方式复现，须写清复现方法。
3. **即时反馈的会话内可见性**：设置页仍打开时点击按钮，反馈必须页面内可见；不得只在关闭设置页后、或只在 Windows 系统界面里才能看到结果（总纲 §2）。
4. **不落盘与配置零污染**：两项均不写配置；用 `QUIKVIEW_CONFIG_PATH` 指向隔离 ini，运行前后记录 `build/config.ini` SHA256，须完全一致；点击按钮前后 ini 读回值一致，不新增键。
5. **三链路运行态与配置回滚**：分别走 取消 / Esc / 标题栏 ✕，配置值**与设置页运行态**（按钮禁用态、状态行、残留弹窗）同时回到进入设置前；非仅比对配置值。ACTION 项不落盘，但仍须证明三条链路不残留状态、不弹二次提示。
6. **失败注入**：`QUIKVIEW_TEST_LIVE_FAIL=1` 下 UI、运行态、配置三者不分叉；不得以「本页无 LIVE 项」为由跳过。
7. **回归**：「保存设置」旧路径不回归、批次01–06 既有 LIVE 项不回归、深 / 浅主题与 100% / 125% DPI 下状态行与弹窗截图；上下文菜单页 0 控件只读状态行不因本批出现假开关；逐格式勾选组不得恢复。未测的外部系统组合（不同 Windows 版本、无网络、无默认应用权限）须单列。
