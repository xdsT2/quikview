## 2. 每项验收点（逐项填表，缺一不可）

1. **ON/OFF 双向行为证据**：两态各一次真实行为触发，至少含反向切回；给触发前后截图（或像素差 / 运行态日志）与 ini 读回值。只记录配置变化不算通过。沿用阶段B §3.1 的触发方式：#10 Shift+TAB 隐藏菜单看浮层、#11 放大→翻页→返回看 zoom、#13 打开多帧 GIF 看「第 n/N 帧」行、#15 真实光标悬停看 Tooltip。
2. **切换即预览**：设置对话框仍打开时变更该项，须有用户可见的即时反馈（见 §3）；阶段B 已证这 3 项「会话内不可观察」，本批**必须解决**，不得沿用「不可」结案。
3. **关闭即保留、不用保存**：不点「保存设置」，以正常退出路径离开设置页，配置值与运行态都保留；重启后读回一致。
4. **三链路运行态回滚**：分别走 取消 / Esc / 标题栏 ✕，配置值**与运行态**（浮层 / 帧号行 / Tooltip / zoom）同时回到进入设置前；非仅比对配置值。
5. **失败注入**：`QUIKVIEW_TEST_LIVE_FAIL=1` 下 UI、运行态、配置三者不分叉。
6. **回归**：「保存设置」旧路径不回归、#12/#14/#16 既有 LIVE 行为不回归、深 / 浅主题与 100% / 125% DPI 下相关状态截图；MNG / 多页 TIFF 与 Tooltip 逐点若未测须单列。
7. **生效时机标注**：每项写清真实生效时机；底部 footer 若仍为「更改会在保存后生效」，须按本批结论同步，不得让「即时项 + 全页统一保存后生效」并存误导用户。
8. 按 `docs/design/UI-REVIEW.md` 模板填报；未测项、未达标项单列并写清原因，**不得写成通过**；仅「配置落盘成功」或「控件状态更新」不构成通过。

## 3. 模态可见性（总纲 §2，本批核心难点）

阶段B 补证回执 §3 / §7 已证：模态 `dlg.exec()` 拦截主窗口交互，#10 / #13 / #15 在设置会话内**不可自然观察**，且这三个键当前**没有** `MainWindow::applyLiveSetting` 分支、`liveSettingValue()` 返回空 `QVariant`。本批须：

- 为这 4 个键补 `applyLiveSetting` 分支与运行态快照（复用 SET-02 框架，不另造轮子）；
- 给出**用户可见的即时反馈**（例如设置页内联状态行 / 预览提示，说明已即时生效及可观察的触发方式），或提供非模态预览入口；
- **不得只把控件换成胶囊、只接上 setter、或只写「会话内不可观察」就算完成**；不得以「配置已写」冒充即时生效。这是总纲 §2 的硬要求，也是本批与阶段B 补证单的区别。
