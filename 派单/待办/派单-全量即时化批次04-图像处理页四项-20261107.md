## 2. 每项验收点（逐项填表，缺一不可）

1. **ON/OFF 双向行为证据**：两态各一次真实行为触发，至少含反向切回；给触发前后截图（或像素差 / 运行态日志）与 ini 读回值。只记录配置变化不算通过。参考触发方式：#20 插值设 Lanczos、缩到约 50% 比对高频边缘（fit 100% 下无差异属预期，须写明条件）；#21 大图目录翻到相邻图的耗时 / 缓存命中日志；#22 设 64 与 2048 翻 20 张大图后回翻命中率与进程内存，并说明越界夹取；#23 适配宽度打开竖长图看顶端对齐 / 垂直居中。
2. **切换即预览**：设置对话框仍打开时变更该项，须有用户可见的即时反馈（见 §3）。条件依赖项不得沿用「会话内不可观察」结案。
3. **关闭即保留、不用保存**：不点「保存设置」，以正常退出路径离开设置页，配置值与运行态都保留；重启后读回一致。
4. **三链路运行态回滚**：分别走 取消 / Esc / 标题栏 ✕，配置值**与运行态**（采样缓存 / 预读行为 / cacheLimit / 大图对齐）同时回到进入设置前；非仅比对配置值。
5. **失败注入**：`QUIKVIEW_TEST_LIVE_FAIL=1` 下 UI、运行态、配置三者不分叉。
6. **回归**：「保存设置」旧路径不回归、批次01/02/03 既有 LIVE 项不回归、深 / 浅主题与 100% / 125% DPI 下相关状态截图；未测的格式样本 / 大图样本须单列。
7. **生效时机标注**：每项写清真实生效时机；footer 按 §1.1 第 2 条同步，不得留「即时项 + 全页统一保存后生效」并存。
8. 按 `docs/design/UI-REVIEW.md` 模板填报；未测项、未达标项单列并写清原因，**不得写成通过**；仅「配置落盘成功」或「控件状态更新」不构成通过。

## 3. 会话内可见性（总纲 §2，本批核心难点）

设置页为模态 `dlg.exec()`，主窗口交互被拦截；图像处理 4 项的消费点又多在「下一次开图 / 下一次重采样 / 解码线程」才读值，容易被误判为「会话内不可观察」而退回保存生效型。本批须：

- 为 4 个键补 `applyLiveSetting` 分支与运行态快照（复用 SET-02 框架，不另造轮子）；#22 数值框须在输入变更后即时下发 `setFullCacheLimit`，并给运行态 `cacheLimit` 的可见反馈（页内状态行或预览提示）。
- 给出**用户可见的即时反馈**（例如设置页内联状态行 / 预览提示，说明已即时生效及可观察的触发方式），或提供非模态预览入口；条件依赖项须写清观察前提并给出该前提下的实证。
- **不得只把控件换成胶囊、只接上 setter、只写「会话内不可观察」或只做时机标注就算完成**；不得以「配置已写」冒充即时生效。这是总纲 §2 与 22:42 最高指令的硬要求。
