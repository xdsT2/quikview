## 二、拆分策略（关键，先说清为什么不能按功能干净拆）

`src/MainWindow.cpp`、`src/ImageCanvas.cpp`、`src/UiStyle.h` **三个文件同时承载 G1/G2/G3 的改动**（交接单已点名）。硬按功能拆会导致中间态编译不过，或提交里带别人的改动。

**允许两条路线，执行侧自行判断后选一条，并在回执里说明选择理由**：

### 路线 A（首选）：按「可独立编译」拆 4 个提交

顺序固定（先独立、后共享）：

1. `feat(dialog): 打开文件对话框「所有图片」置首` —— 只动 G4 两个文件

## 四、G5 专项注意：NSIS 是 UTF-16

`packaging/quikview.nsi` 在 Git 里呈现**二进制差异**（UTF-16 编码）。改之前：

```bash
file packaging/quikview.nsi                       # 确认编码
iconv -f UTF-16LE -t UTF-8 packaging/quikview.nsi | head -30   # 只读预览
```

- 改完必须保持原编码回写，否则 NSIS 编译会报「Invalid UTF-8」或直接乱码；
- 对比改动时不要用 `git diff`（会显示为二进制），用 `iconv` 转 UTF-8 后再 `diff`；
- 打包后必须用 7z 解包 setup 抽验内部 `quikview.exe` 的 SHA256 与 `dist/` 里一致（NSIS 压缩 payload 里 grep 不到明文属正常，别误判）。
