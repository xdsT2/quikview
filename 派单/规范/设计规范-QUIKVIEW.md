## 0. 一句话标准

**Windows 11 深色、成熟、克制、有质感；主窗口、菜单、设置页、对话框不能像四个不同的软件。**

## 1. 气质边界

**要做**：清晰的信息层级、稳定的间距节奏、克制的强调色、可预测的控件状态、统一的图标语言。

**不做**：
- 渐变叠加、发光描边、大面积玻璃拟态（已批准的磨砂菜单除外）、超过 10px 的卡片圆角
- 无意义的 hover 缩放/位移、超过 200ms 的装饰性动画
- emoji 当图标、混用实心与线性图标
- 为"高级感"牺牲启动速度、滚动流畅度或 Windows 原生交互习惯

## 4. 间距与尺寸

### 4.1 布局间距（默认规则）

元素之间、页边距、节间距、列间距一律取 **4 的倍数**。新增布局间距违反此条即不通过。

### 4.2 已实测例外登记表

控件自身尺寸与少数经视觉验证的偏移允许非 4 倍数，但必须在此登记并附截图依据。**未登记就使用 = 不通过。**

| 例外面 | 值 | 依据 | 状态 |
|---|---|---|---|
| 设置页内容上边距 | 25px | 与 43px 标题栏、20px 下边距配合的视觉重心 | 已实测 |
| 导航外边距 | 10 / 16px | 与 204px 宽、33px 条目配合 | 已实测 |
| 导航条目间距 | 2px | 条目密集，4px 显散 | 已实测 |
| 行控件最小高 | 23px | 12px 字 + 行距，再低会挤 | 已实测 |
| 输入框 / 按钮高 | 30px | 点击目标与信息密度平衡 | 已实测 |
| 标题栏 / 底部条 | 43 / 62px | 铬件比例 | 已实测 |

## 5. 控件状态（缺一不可）

默认 / 悬停 / 按下 / 焦点 / 禁用 / 选中，六态都要能分辨。

- **禁用**不等于"把字调暗"：文字仍要可读（≥3:1），并给出原因（tooltip）。禁用态不得显示与真实行为矛盾的状态。
- **未实现的项不许留可交互假开关**：要么实现，要么移除；确需保留说明，用只读状态行。
- **焦点**必须有可见指示，且不能只靠颜色：需 2px 描边或 3:1 对比差。

## 6. 一致性

- 同一动作在不同入口**同名**（"打开" / "打开文件夹" 不得混用）。
- 图标同一套、两档尺寸（16 / 20），同语义不得一处线性一处实心。
- 对话框按钮：主操作在右，取消在其左；危险操作使用 `Danger` 且需二次确认。
- 空态、错误态、加载态三态都要有，文案说明"下一步能做什么"。

### 7.2 判定规则

1. **承载信息的文字 ≥ 4.5:1**。本项目界面文字最大 21px 且为标题，不存在"大号次要文字"，因此**不启用 3:1 大字豁免**。
2. **`Dim` 只允许装饰用途**（不承载用户完成任务所需的信息）。它在任何背景上都达不到 4.5:1；现存的 11px 说明文字使用 `Dim` 属**存量债务**，基线评审逐处记 P1，改为 `Muted` 或并入 `Body`。**不要整体调亮 `Dim` 来糊弄矩阵。**
3. **`Muted` 不得用于 `Hover` 背景上的小字**（4.00 不达标），悬停/选中态文字改用 `Body`。
4. **控件边界 ≥ 3:1**：`Border` 对 `Field` 仅 1.61、对 `Panel` 1.84，且 `Field` 与 `Panel` 底色差仅 1.14——输入框实际靠描边识别，**当前不达标**。列为全局 P1：方向是把描边提亮到约 `#787878`（对 Field 3.03 / Panel 3.47）或改用更明确的填充差，**必须截图验证后再定值**，不得直接改。
5. 装饰性分割线不受 3:1 约束（`Line` / `Line2` 保持现状）。

### 7.3 浅色矩阵（2026-11-05 实测，v1.2 新增）

v1.1 只有深色矩阵，浅色主题因此长期没有验收依据——2026-11-05 用户反馈「白色面板太丑」，
实测发现导航未选中项只有 **1.47:1**、语言页链接 **1.99:1**，都是没有被矩阵挡住的问题。

**浅色令牌（`UiStyle::pick(深, 浅)` 的第二参数，唯一来源仍是 `src/UiStyle.h`）**

|---|---|---|---|
| `Bg` | `#101113` | `#e8eaed` | 应用底 |
| `Window` / `ChromeBg` | `#17181b` / `#161719` | `#f3f4f6` | 窗口底 |
| `Panel`（内容区） | `#242528` | `#ffffff` | 最前层，纯白 |
| `DialogBg` | `#232427` | `#f4f5f7` | 对话框外框 |
| `TitleBg` | `#25262a` | `#f2f4f6` | 标题栏 |
| `NavBg` | `#1e1f22` | `#e6e8eb` | 导航栏（压深以分层次） |
| `FooterBg` | `#222326` | `#eceef1` | 底栏 |
| `Field` | `#2d2f34` | `#ffffff` | 输入框底（靠描边识别） |
| `Text` | `#f2f2f2` | `#1b1b1b` | 主文字 |
| `Body` | `#d5d7da` | `#202124` | 正文 |
| `Muted` | `#92979e` | `#5f6368` | 次要文字 |
| `Dim` | `#686e76` | `#8a8f94` | 仅装饰 |
| `NavText` | `#bfc3c8` | `#4a4d51` | 导航项常态（**不得直接用深色常量**） |
| `LinkText` | `#55c0f0` | `#0b6f9f` | 链接文字（**不得直接用 `Accent`**） |
| `Border` | `#787878` | `#999999` | 控件描边 |

**层次（相对内容区 `#ffffff`）**

| 层 | 浅色值 | 对比 | 判定 |
|---|---|---|---|
| 内容区 `contentPane` | `#ffffff` | 1.00 | 基准 |
| 导航栏 `navRail` | `#e6e8eb` | **1.23** | ✅ 人眼可分（阈值约 1.2） |
| 底栏 `dlgFooter` | `#eceef1` | **1.16** | ✅ |
| 标题栏 `dlgTitleBar` | `#f2f4f6` | 1.10 | ✅ 靠 1px 分隔线补足 |

> v1.1 时期的四层是 1.06 / 1.13 / 1.11，全部低于 1.2，等于没有层次——**浅色层次必须
> 靠「外框压深、内容最前」表达，不能像深色那样靠「越亮越前」**。

**文字实测（对各自底色）**

| 角色 | v1.1 实测 | v1.2 实测 | 要求 |
|---|---|---|---|
| 导航未选中项 | **1.47** ❌ | **6.92** ✅ | ≥4.5 |
| 导航分组名 | 4.15 ❌ | 5.23 ✅ | ≥4.5 |
| 底栏说明 | 4.24 ❌ | 5.52 ✅ | ≥4.5 |
| 页面副标题 / 脚注 | 4.70 ✅ | 6.05 ✅ | ≥4.5 |
| 语言页链接 | **1.99** ❌ | **5.54** ✅ | ≥4.5 |
| 节标题 | 15.14（过黑） | 13.62 ✅ | ≥4.5 |

**浅色专属规则**

1. **半透明底一律不得用于浅色浮层**。白色 alpha 会吸收背景彩度（实测 alpha 0.92 压红条
   得 `(246,226,227)`、压绿条得 `(225,247,227)`），深色 alpha 只压暗不改色相。浅色浮层用
   不透明 `#ffffff` + 1px 描边。
2. **纯白不能当"有边界"用**。直方图井、卡片等在白底上必须另给 `#f2f3f5` 或描边。
3. **深色常量禁止直接进浅色路径**。`NavText` / `Accent` 这类"看着通用"的常量在浅色下会
   掉到 1.5–2.0:1；一律走 `pick()` 或语义函数（`navText()` / `linkText()`）。
4. **浅色改动必须附深色零回归证据**：深色路径不得变一行，改完复拍深色同一场景。

## 8. 验收协议（硬性）

### 8.1 测试隔离（执行前必做）

评审与截图**不得跑在正在使用的工作区**，否则配置、版本、截图三者对不上。

```bash
# 1) 干净工作树，锁定被评审的提交
git -C <repo> worktree add ../qv-review <commit>
git -C ../qv-review rev-parse HEAD        # 写进报告

# 2) 独立构建目录，配置随之隔离（便携模式：exe 同目录 config.ini）
cmake -S ../qv-review -B ../qv-review-build -G Ninja -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_PREFIX_PATH=/e/Agent/Tencent/WorkBuddy/Workspace/tools/msys64/mingw64
cmake --build ../qv-review-build

# 3) 每批跑前清空该目录的 config.ini；跑完配置留在评审目录，不碰主工作区
```

- 冒烟测试会写真实配置：**必须在隔离目录里跑**，跑完不得把配置带回主工作区。
- 单实例：跑批前 `taskkill //IM quikview.exe //F`。
- 高 DPI：`QT_SCALE_FACTOR=1` / `1.25` / `1.5` 各跑一轮，分别存档。

### 8.2 截图

只能用程序自渲染（禁止抓屏）：

```bash
./build/quikview.exe "<一张图>" --screenshot out.png --shot-delay 1200 --smoke "settings"
```

可用命令：`settings` `viewmenu` `ctxmenu` `tabtoggle` `browser` `info` `lockdock` `locktop` `next10` `zoomout` `zoomin` `spread:l2r` `keyconflict` `report`。

深浅两套都要看；未覆盖浅色的页面必须写明。

### 8.3 证据类型（按问题类型取证据）

| 问题类型 | 必需证据 | 不接受 |
|---|---|---|
| 视觉（间距、对齐、层级、颜色） | 运行截图 + 坐标/像素采样 + 规范条款号 | 代码行、"看起来" |
| 行为（开关是否生效、快捷键、状态机） | 代码路径 + 实际操作验证（真实事件或探针输出） | 仅凭截图 |
| 配置（键是否被消费） | 配置文件真实值 + 消费点 grep + 保存/重载验证 | 仅看界面显示 |
| 性能（卡顿、内存、启动） | 测量数据（耗时/内存/帧数），同机同图对比 | 主观感受 |

一条结论可同时需要多类证据；缺哪类就标"未验证"，**不得写成通过**。

## 9. 评审输出格式

每条给出：**位置 → 问题 → 证据（类型 + 具体值）→ 期望值 → 一句话理由**。

| 级别 | 判据 | 处理 |
|---|---|---|
| **P0 阻断** | 看起来像坏了；不可读；状态与真实行为矛盾；高 DPI 错位 | 修完才能交付 |
| **P1 明显** | 间距错、层级乱、缺状态、文案不一致、对比度不达标 | 本期内修 |
| **P2 打磨** | 1px 偏差、色差、措辞 | 可排期 |

"更高级""更现代""感觉舒服"不是验收标准，不得出现在结论里。

## 10. 与设计技能的关系

| 技能 | 用法 | 红线 |
|---|---|---|
| `ui-ux-pro-max` | 设计方向、配色/字体/布局规则、反模式清单 | 只取规则，不照搬它给的框架代码 |
| `better-layout` / `better-typography` / `better-colors` / `better-ui` | 分别检查间距层级、字阶、配色对比、边框阴影图标 | 输出检查结论；落地值以本规范令牌为准 |
| `better-interface` / `interface-review` | 综合审查并按严重度排序 | 必须附截图证据与类型标记 |
| `frontend-design`（未安装） | 避免千篇一律 | 仅参考，不作 Qt 实现规范 |

**统一约束**：技能里的 CSS 数值（`rem`、`outline`、`box-shadow` 等）一律先翻译成本项目像素与令牌，再落地。

## 12. 变更流程

1. 新增/修改界面前先查本规范；找不到约束就补一条。
2. 改 `UiStyle.h` 令牌值必须同步更新 §2；新增例外必须登记 §4.2。
3. 每个改动附证据（类型按 §8.3），按 §9 输出。
4. P0 未清零不得交付；P1 未清零不得发版。
