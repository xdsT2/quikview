# QuikView 视觉与交互规范

> 项目级规范，供所有开发者与编码 Agent 共用。生效日期：2026-11-05。  
> 项目级规则在本文维护，令牌实现以 `src/UiStyle.h` 为准。

## 1. 产品气质

Windows 桌面图片查看器：成熟、克制、清晰、响应快。主窗口、菜单、设置页和对话框应像同一个产品。

避免无意义渐变、发光、大面积玻璃效果（已批准的磨砂菜单除外）、过大圆角、装饰性动画、emoji 图标，以及牺牲性能或 Windows 原生交互习惯的设计。

## 2. 技术边界

- 项目使用 Qt Widgets/QSS；按现有 QWidget、QStyle、布局和 `UiStyle` 模式实现。
- Web 设计 Skill 可用于信息层级、布局、字体和审查思路；禁止把 CSS、DOM 结构或 Web 控件代码直接套到 Qt。
- 颜色从 `src/UiStyle.h` 令牌读取。新增界面代码不得散落裸色值；必要的新令牌须先进入 `UiStyle.h` 并更新本规范。
- 复用现有字号、间距、控件尺寸和图标系统；例外须说明理由并有实际截图依据。

## 3. 基础视觉规则

- 默认深色基线见 `src/UiStyle.h`。主文字、正文、次要文字使用各自语义令牌，不以低对比度隐藏信息。
- 字重优先 400/600；布局间距优先 4 的倍数。
- 控件圆角沿用项目已有档位，新增尺寸须登记，避免同层级控件各自随意设值。
- 所有交互控件考虑默认、悬停、按下、焦点、禁用、选中状态；焦点必须可见。
- 禁用项仍需可读并解释原因；未实现功能不能保留可操作的假开关。
- 一次性动作使用按钮；互斥档位使用下拉/单选；二态使用开关/复选框；连续数值使用数值输入或滑块。控件文案和实际行为必须一致。
- 设置项需说明真实生效时机（即时、应用后、重启后或依赖外部条件），即时预览须支持取消回滚。

已登记的控件尺寸（实现见 `src/UiStyle.h`）：

| 控件 | 尺寸 | 依据 |
|---|---|---|
| 胶囊拨动开关 `PillToggle` | 轨道 40×20、圆角 10、滑块 12、内边距 2、焦点环外扩 2 | 对齐 WinUI 3 ToggleSwitch 的滑块/轨道比例；2026-11-09 滑块由 16 调为 12（原 16 在 20px 轨道里只剩 2px 上下留白，视觉偏满） |

## 4. 颜色与令牌

`src/UiStyle.h` 是令牌值的唯一事实来源。评审时检查新改动是否复用语义令牌，不在规范副本里另造代码值。以下是当前主要深色令牌基线，若与源码不符，以源码为准并同步更新本文：

| 语义 | 令牌 | 当前值 |
|---|---|---|
| 应用底 | `Bg` | `#101113` |
| 窗口底 | `Window` | `#17181b` |
| 命令栏 | `Bar` | `#202124` |
| 内容面板 | `Panel` | `#242528` |
| 次级面板 | `Panel2` | `#2a2c30` |
| 输入底 | `Field` | `#2d2f34` |
| 悬停 | `Hover` | `#35383e` |
| 主文字 | `Text` | `#f2f2f2` |
| 正文 | `Body` | `#d5d7da` |
| 次要文字 | `Muted` | `#92979e` |
| 强调 | `Accent` | `#55c0f0` |
| 描边 | `Border` | `#787878` |

设置页排版统一（2026-11-07）新增语义令牌，深浅值见 `src/UiStyle.h`：分组卡片底 `setGroupBg`、卡片/行分隔线 `setGroupLine`、整行悬停底 `setRowHover`、只读状态标签 `setRowTag`。普通设置行沿用 40px 行高、左右 11px 内边距、12px 控件间距，不做绝对定位或写死控件坐标。

浅色主题必须使用项目已定义的浅色令牌/映射并实际截图检查；不可只反转背景而忽略图表、图标、透明高光或禁用态。

## 5. 可读性与布局

- 信息文字对比度目标至少 4.5:1；控件边界/焦点按项目无障碍基线检查。
- 标题、描述、操作区域有明确层级；相邻页签控件对齐；长文本不得被截断到无法完成任务。
- 滚动区域需实测首末项、滚动条和底部留白；“没有半行”不代表布局已通过。
- 深色/浅色主题、常规与高 DPI、长文案和小窗口按改动风险选择验证矩阵，并写出未测项。

## 6. 不可妥协项

1. 不能只凭代码自评美观，必须查看程序自渲染结果。
2. 不能为高级感堆砌装饰效果。
3. 不能以“配置保存成功”代替设置功能真实生效。
4. 不能把未实测、环境不支持或只部分支持写成通过/完整支持。
5. 不得因视觉改动破坏速度、稳定性、键盘操作、焦点可见性和系统集成行为。

## 7. 来源与维护

本文将原本被 `.gitignore` 排除的本地设计规范整理为仓库可见版本。维护时检查 `UiStyle.h`、设置页实际布局和最近已验收基线；更新本文需说明变更依据，避免规范与产品代码分叉。
