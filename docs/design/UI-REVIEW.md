# QuikView UI 设计与验收流程

## 何时使用

任何涉及界面、视觉样式、交互控件、设置页、图标、文案布局或主题的工作都适用。按任务使用可用的设计 Skill：

- 方向、页面结构或新功能：`ui-ux-pro-max` 提供设计方向与模式参考。
- 局部细节：`better-ui`、`better-layout`、`better-typography`、`better-colors`。
- 完成后综合审查：`better-interface`。
- `frontend-design` 仅用于寻找视觉方向；它偏 Web，不能直接提供 Qt 实现。

如果当前 Agent 无法调用某 Skill，直接按本流程和 `QUIKVIEW-DESIGN.md` 执行，并在记录中注明。Skill 不是项目规范的替代品。

## 流程

### 1. 改前确认

- 描述用户遇到的问题、目标页面和不在范围内的内容。
- 查看 `QUIKVIEW-DESIGN.md`、`src/UiStyle.h` 和现有截图/基线。
- 说明复用的组件/令牌；新布局先明确层级、状态及窄屏/高 DPI 行为。
- 对设置项，先确认功能真实存在、运行时消费路径和生效时机；不确定就列为待验证。

### 2. 实现自检

检查层级、间距、对齐、文字完整性、图标一致、状态完整、颜色对比、键盘焦点、主题一致性、滚动末端、DPI 和功能真实性。设置控件需验证实际行为，不以配置值变化代替。

### 3. 运行与截图

- 构建当前目标并运行真实程序，使用项目已有自渲染截图/自动化入口；不要只展示 mockup。
- 截图须覆盖改动页面、主要主题和关键状态；布局变更检查末端与缩放；颜色变更检查深浅主题；控件变更检查 hover/focus/disabled/selected 中相关状态。
- 视觉截图用于视觉验证；动态行为须用实际操作、探针或日志验证，静态图不能证明即时生效。
- 不污染用户配置。运行 smoke 前记录配置哈希；优先使用隔离配置路径。

### 4. 评审与修正

可用时先应用对应 Skill，再用 `better-interface` 做综合评审。每个问题写明位置、截图证据、严重度和预期结果。修正 P0/P1 后重拍同一场景，并做相关功能回归。

问题等级：

- **P0 阻断**：不可读、无法操作、严重错位/遮挡、关键功能无效或数据风险。
- **P1 明显**：主要层级、对齐、对比度、状态或响应行为错误，普通用户容易发现。
- **P2 打磨**：局部节奏、细节一致性或非关键状态优化。

## UI 验收记录模板

```text
任务 / 提交：
改动页面与用户问题：
设计依据 / 使用的 Skill（未安装则注明）：
构建命令与结果：
运行环境：Windows / 分辨率 / DPI / 主题 / 窗口尺寸
截图文件：改前、改后、状态图
实际操作与结果（设置项必须包含开/关或选择切换、保存/重启、取消回滚）：
审查发现：严重度 / 位置 / 证据 / 期望
修正后复验：
未测试项与原因：
结论：通过 / 部分通过 / 未通过
```

## 交付门槛

UI 工作只有在真实运行结果已查看、相关行为已验证、问题已修正或明确留项、未测试部分已标注后才能通过验收。纯源码检查、构建成功或“截图看起来差不多”均不构成完整验收证据。
